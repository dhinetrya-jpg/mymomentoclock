## Pipeline and authority

`backend/internal/timing`: Request→Validated (existing ephemeris.ParseBirth)→Provider Inputs→Registry→predicate interval intersection→global exclusions→overlap partition/merge→stable ranking→Result. Inputs bind to the entire request, exact birth UTC and target day; contradictory facts, missing coverage, mismatched mode or missing solar events produce INSUFFICIENT_EVIDENCE. Providers must return immutable per-request facts. No facts, rules, approval flags or profile references are accepted from browser requests.

The only native binding is deliberately blocked: no independently admitted native natal/Panchang/solar provider is available. A test Provider supplies synthetic facts; only those can exercise the algorithm and always return PROVISIONAL/SYNTHETIC, never verified guidance. Non-synthetic input status strings cannot open the gate. Actual Swiss astronomy is not recalculated in Node/React or replaced by browser approximations. Future acceptance requires reviewed binding to independently validated native contracts, not an environment toggle.

Intervals are absolute UTC `[start,end)`. Local days resolve two IANA civil midnights with existing DST logic, not start+24h; ambiguous/nonexistent midnight boundaries fail closed. Birth range1900–2100 and target2000–2100. UNKNOWN and APPROXIMATE birth times return insufficient evidence; no arbitrary uncertainty/confidence percentage. Fold times require an explicit matching UTC offset. Overlapping includes split into nonoverlapping segments; exclusions always win. Adjacent segments merge only with the same rule set/precedence. Ranking is explicit configured rule priority, longer duration, earliest start, lexical rule IDs. Rank is ordinal, not probability. With fixed clock/source inputs full output is deterministic; request timestamps naturally change between calls, windows/ranking do not.

## Contracts and privacy

GET `/api/v1/timing/activities`, GET `/api/v1/timing/capability`, POST `/api/v1/timing/daily` on Node and native Go. New routes do not reactivate legacy personal Muhurat. Strict bounded bodies (16KiB timing/64KiB outer web), no query selectors, safe error codes, no-store, no persistence/logged birth data. Native validation remains authoritative. Node can delegate to an approved HTTPS internal mTLS front using TIMING_INTERNAL_URL/CA_FILE/CERT_FILE/KEY_FILE; only localhost, `.internal` or `.svc.cluster.local` hosts, exact path, certificate validation, timeout and response bounds. Missing transport returns typed unavailable. Native standard HTTP requires an approved private TLS front/sidecar for that optional deployment; none was deployed.

Even a configured Node gateway rejects upstream fixture/success/approval claims: it currently projects only empty unavailable/insufficient responses. Requested ephemeris mode is separate from actual UNAVAILABLE/SYNTHETIC mode. No runtime flag, remote report or payment entitlement can authorize timing. Existing Node/Go request concurrency and rate bounds remain in force.

React Daily Timing is independent of the analytical chart: explicit birth/target coordinates, IANA zones, uncertainty/offset and six activities; no geocoding API, saved profile or localStorage. Timeline positions represent actual elapsed local-day duration (23/24/25h etc.), labels include offsets, and list explanations remain accessible without color. Synthetic timelines are only browser-test fixtures with explicit warning. Editing input clears prior results; unmount aborts requests. No new packages or external astronomical APIs.
